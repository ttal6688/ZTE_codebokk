# UPA单极化单流：基线、共相位与反馈协议修正报告

日期：2026年10月23日。当前版本UPA_SINGLE_PROTOCOL_V2。Git分支：`fix/single-stream-protocol-baselines-20261023`。本轮修改位于新Git分支的原`8.单流`目录，不修改main或其他已有分支，不新建顶层文件夹冒充分支。

本轮目的：把单流基线定义、相位规则、CPU/UE可用信息和反馈开销统一到可以独立重建的实现，再做最小验证。已验证实现闭合，不作400位置性能排名，也未开始双流。

## 1 从最初代码继承什么、修正什么

对照仓库最初提交fd8a2c7中的`1.仅含HAQSE`和`2.对比方案`，以及前阶段UPA/POS修复提交4622561。最初两目录从初始提交到当前main没有修改。

| 问题 | V2处理 | 为什么这样处理 |
|---|---|---|
| 新入口Type-I按本地能量选波束 | 恢复全部AP联合主右奇异向量分块选波束 | 接续原型的共同目标模式，避免同名算法含义变化 |
| Type-II直接选过采样码本最强两条 | 恢复同一正交分组内选两条，遍历分组并比较两条投影能量和 | 避免将高度相关的相邻波束当作原型的正交双波束组合 |
| Type-I/II顺序贪婪，其他方法主模式投影 | 五种普通UE方法统一主模式投影，4 bit相对相位 | 将相位优化器的差异从主实验中移除 |
| 最初注释写量化，实际共享函数用连续相位 | 明确统一4 bit是本轮的新实验条件 | 不把连续/8 bit混用的原型当作公平量化基线 |
| 最初保留三个AP实测信道拼接重构信道 | 当前CPU只用消息与公共几何，不接收这些信道块 | 使低反馈链路的信息和开销一致 |
| 反馈量已计费但没有完整重放 | 所有可实施方法打包整数比特串，CPU独立解码 | 预编码实际由所计费的消息生成 |
| CPU“固定估计维度”含义混杂 | 移除旧字段，分别记录参考数、参数数、观测量、模型尺寸及解码时间 | 不把固定R误写成整个CPU复杂度固定 |
| POS截断可能掩盖定位误差 | 同时保存原始/解码误差和越界率，保留所有预定样本 | 区分定位、坐标量化和区域先验的影响 |
| 仅SVD不能分离CSI影响 | 六种UE算法均增加同算法观测/完美CSI配对 | 保持码本、量化和功率约束一致 |
| 400 MHz、Docomo身份不明确 | 明确窄带换算，保留“Docomo结构适配”名称 | 不宣称OFDM仿真或未经核验的原算法复现 |

已经修好的UPA和POS前端继续保留：每AP为8×8、16×16或32×32 UPA；POS由连续HAQSE二维频率在UE定位后，直接量化三维坐标。HAQSE频率反馈仍量化频率，两种方法不混为一条链路。

## 2 UE计算：如何实现

### 空间波束

Type-I：对全部活动AP的观测信道求联合主右奇异向量，按AP分块，各自匹配二维DFT码字。不是每AP单独追求最大接收能量。

Type-II：在上述分块上计算码字投影；对每个正交DFT分组保留两条最强码字，选择两条投影能量和最大的分组。第一条为幅度1、内部相位0的参考，第二条相对幅度3 bit、内部相位2 bit。复合后每AP归一化。相位正负号按原始复投影关系处理，并通过旧基线及显式码字检查。

HAQSE/DFT/POS：UE先编码空间信息，再使用CPU相同的解码规则生成最终空间波束。POS的全部AP波束均来自解码坐标；HAQSE/DFT的参考AP保留消息中的直接方向，其他AP由定位推断。没有用UE未量化位置直接设计CPU最终波束。

### 共相位

令每AP波束为f_b，联合主模式分块为v_b。计算投影`a_b = f_b^H v_b`，取相对首AP相位`angle(a_b) - angle(a_1)`，再量化为16个圆周相位之一。首AP固定0，其余B−1项各4 bit。

五种普通方法使用同一规则；它是明确的投影启发式，不宣称固定波束下的全局速率最优。Docomo属于独立结构适配，保留其QPSK beta和AP逻辑DFT，不替换为普通相位规则。

### CPU恢复

UE将波束索引、内部组合整数及AP相位整数打包成实际有效载荷。CPU独立读取比特串，重建码字、Type-II组合与归一化，再生成发送向量。最终评价使用的就是该恢复向量，不直接使用UE生成的浮点波束。

总发送功率1，各AP功率1/B；UE没有额外AP幅度反馈。首AP相位先固定、再量化，B−1项计费与实际字段一致。

## 3 CPU计算：如何实现

UE只提供三个参考AP的空间消息。CPU通过[decode_feedback](../+sstr/decode_feedback.m)接收公共net、活动AP顺序、比特串、方法和预先约定的模式，接口不接收Hobs、Htrue、参考AP实测信道块或连续UE定位结果。

CPU解码位置与每AP波束，再以公开AP中心、阵列朝向、UE阵元偏移和LOS传播模型构造4×BN模型。对模型求联合主模式、投影到波束，生成连续相对相位。该相位由CPU计算，不计UE相位反馈。

仿真器为诊断保存的连续频率、原始位置和真实位置，不属于CPU消息；真实信道只在性能评价阶段使用。Type-I/II在CPU图中明确标为UE参考，SVD为理想上界，不能将它们解释成CPU低反馈算法。

固定的是R=3和空间有效载荷维数。参考观测约为4NR个复数，在UE发生、随N增长；模型4×BN和输出B组权重的工作量仍增长。当前不模拟导频协议，不声称固定导频符号数或固定整体复杂度。

## 4 反馈格式及实际默认开销

实现见[feedback_wire](../+sstr/feedback_wire.m)。整数MSB优先、矩阵按列编码；每条记录保存人可读整数消息及对应比特串。解码器拒绝不完整/多余比特和未约定的连续估计字段。

方法、模式、AP顺序和冻结量化配置为公共配置，统计有效载荷，不含所有方法共同排除的传输头、FEC与字节填充；没有把JSON文件字数当作反馈量。

默认32×32、B=8：

| 方法 | CPU几何有效载荷 | UE有效载荷 |
|---|---:|---:|
| HAQSE，R=3 | 84 bit | 112 bit |
| DFT索引，R=3 | 42 bit | 70 bit |
| POS，R=3 | 36 bit | 64 bit |
| Type-I | UE参考 | 140 bit |
| Type-II | UE参考 | 292 bit |
| Docomo结构适配 | 不参加CPU几何链路 | 129 bit |

Type-II直接发送两个完整码字索引，未利用正交关系进一步压缩，开销与实际格式一致。POS冻结13/14/9 bit，不随当前位置或AP数改变；无需另传动态分配标识。坐标bit随位置图如实显示固定分配，未伪造自适应变化。

## 5 最小验证：范围、过程和结果

| 验证 | 范围 | 结果 |
|---|---|---|
| 协议单元检查 | 三种UPA、B=5/8/10、81种完整消息案例 | 701项通过 |
| 前阶段UPA/POS回归 | FFT与显式码字、连续频率定位、POS消息独立解码等 | 42项仍通过 |
| 两位置验证 | 399、400；四组N/B设置；LOS和MIX分别运行 | 304条记录，96组CSI配对 |
| 四位置流程验证 | 1至4；12个参数标签；MIX | 912条记录，288组CSI配对 |
| 独立Python核验 | 上述全部1,216条记录，含1,088条有限反馈记录 | 完整消息、空间波束、AP系数、预编码检查量、全部反馈长度及均值通过 |

总计6个不同预定位置、64个信道/参数案例。不是1,216个位置，也不是正式400位置扫描。CPU中的UE参考重复用于展示，不当作新独立样本。

MATLAB检查UE预期预编码与实际比特解码后的完整向量，最大差异0。独立Python使用另一份解码与几何计算实现，最大预编码检查量误差约1.12×10⁻¹¹，CPU系数误差约1.28×10⁻¹¹。Type-II所选两条波束的最大内积幅度约6.89×10⁻¹⁶。全部汇总均值由Python重算，而非只检查文件存在。

单元检查还验证主模式整体旋转不改变相对相位整数；短一位、长一位和夹带原始位置的消息会被拒绝。空间波束通过前阶段冻结UPA基线回归；小阵列额外使用显式完整码本与普通SVD计算作为独立算法检查。

### CPU结果单独说明

三个空间消息链路均可仅凭比特串和公共几何恢复发送向量，不需要最初方案中的三个AP完整观测信道。固定反馈量与模型规模增长已分开记录。

本轮POS未发生越界；这只说明本组小样本未覆盖到越界事件，不说明完整区域永远不会越界。以四位置MIX的CPU统计为例，K=0/10/20 dB时，原始定位均值约0.02427/0.00825/0.00272 m，坐标解码后约0.02490/0.00863/0.00395 m。量化增加了部分误差，未把它描述成提高定位精度。

### UE结果单独说明

六种算法均完成相同格式的观测/完美CSI配对，共384组；其中55组速率差为负，未剔除或改写。主模式投影及离散码本不是实际速率全局优化，因此完美输入信息不保证这一启发式每个样本都提速。

四位置默认点，Type-I完美CSI减观测CSI平均约−0.780 Mbps，Type-II约+0.973 Mbps；其余四种得到相同的最终离散预编码。不能把这些小样本差异提升为算法排名，也不能仅用与SVD的差距代表CSI损失。该配对用于观察同一算法对CSI的响应。

## 6 当前结论与仍保留的边界

本轮可以确认：基线定义已统一、相位规则可解释、消息和反馈bit对应、CPU不依赖未发送的参考信道块、所有方法可由完整整数反馈生成单流预编码。原数据和冻结依赖未修改。

当前不确认方法性能排名、完美CSI必然提速、整个CPU计算维度固定、Docomo原始实现等价性、完整400 MHz宽带性能或双流可行性。400 MHz仅用于`速率Mbps = 400 × SE`；另保存接收功率、归一化功率增益和频谱效率，数据链路rho与观测SNR分开。

完整400位置入口已保留，但本轮未运行。后续可以在此版本上进行正式单流扫描，再推进已讨论的“同一空间波束＋每AP第二流独立相位”，不从历史双极化报告推断单极化双流结果。
