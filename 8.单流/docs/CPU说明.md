# UPA单极化单流：CPU计算

## 实现步骤

1. UE只对三个参考AP生成空间消息。HAQSE量化二维频率；DFT反馈二维码本索引；POS用连续HAQSE频率三维定位，然后只量化一次坐标，固定13/14/9 bit。
2. 消息打包成实际比特串。CPU接口` sstr.decode_feedback(net,active,wire,method,mode) `只接收公共配置和比特串；不接收观测信道、真实信道、参考AP实测信道块或UE连续位置。
3. CPU解码位置及每AP波束。HAQSE/DFT参考AP使用直接方向，其他AP由定位推断；POS全部AP波束由解码坐标生成。
4. CPU仅凭解码位置与公开几何构造LOS模型，求联合主模式，投影到各AP波束，生成连续相对相位。首AP相位固定0，无相位反馈。
5. 每AP波束单位范数，总功率1、每AP功率1/B；真实信道只在仿真评价阶段使用。

这是对最初方案的信息边界修正：最初方案保留三个AP的观测信道、拼接其余AP的重构信道；当前CPU低反馈链路不再依赖这些实测信道块。

## 开销与统计

默认B=8、32×32 UPA时，HAQSE/DFT/POS有效载荷为84/42/36 bit。固定的是R=3和空间消息数量，不是整个CPU计算量。CPU仍构造4×BN模型；UE为生成参考消息观察的原始信道量为4NR个复数，随N增长。没有实现导频协议，不把R直接写成导频符号数。

定位量化前误差、坐标解码后误差、越界比例分别保存；不能将截断到区域边界带来的改善称为量化收益。量化前连续位置仅为仿真诊断，不传给CPU设计器。

CPU图中的Type-I/II明确标注UE参考，它们在UE使用全部AP的CSI；SVD为理想上界，不属于CPU几何方法。CPU和UE输出分目录，LOS/MIX数据不混合平均，主图使用MIX。

## 验证结果

V2两位置验证含LOS与MIX、三种UPA尺寸和多个AP数量；四位置MIX验证覆盖全部扫描与出图。独立Python程序从比特串重建位置、空间波束、CPU模型相位和预编码检查量，核对所有反馈长度及分组均值。当前是实现可行性和消息闭合验证，不是400位置性能结论。
