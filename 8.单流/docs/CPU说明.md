# UPA单流CPU链路说明

当前入口已适配UPA，POS前端已改为连续HAQSE定位后只量化坐标；本阶段为小样本修复验证，不是400位置正式性能结论。

## 计算过程

1. UE对R=3个参考AP估计连续二维HAQSE频率。HAQSE频率反馈方法量化这两维频率；DFT反馈二维空间索引；POS则直接用连续频率三维定位，再量化坐标13/14/9 bit。
2. CPU从整数频率、方向或坐标消息恢复位置及波束。HAQSE/DFT参考AP保留直接方向，POS包括参考AP在内的全部波束都从解码坐标生成。
3. CPU用公开UPA几何构造4×BN的LOS模型，再投影到每AP空间波束，计算单流AP间相位。该相位不需要UE反馈。
4. 每AP发送相同数据符号，总功率1、每AP功率1/B；最终速率使用真实仿真信道评估。

固定的是参考AP数量以及几何消息规模，不是矩阵维度或CPU复杂度。默认UPA32×32、B=8时，HAQSE/DFT/POS为84/42/36 bit。

POS由独立posfb.decode接收整数坐标消息和公开配置，不读取UE未量化位置。CSV保存space_message、量化前位置、三维解码位置和越界标记，可重放审计。

## 范围

CPU图中的Type-I/II是使用UE观测CSI的共享基线，理想SVD使用真实CSI；它们不是CPU仅凭三个参考AP空间消息生成的方案。Docomo不列入CPU几何方案。

本次不恢复旧Type-I/II的联合主模式和正交分组规则，也不运行双流。新的小样本数据见 [修复说明](UPA与位置反馈修复说明.md)，旧400位置归档仍见 [历史数据索引](../results/single_stream_full/README.md)。
